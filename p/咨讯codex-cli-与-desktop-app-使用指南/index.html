【咨讯】Codex CLI 与 Desktop App 使用指南

~从命令行到桌面应用，掌握 Codex 的日常开发工作流~

2026-08-06
2026-08-07

[!NOTE]

  • 本文章为codex制作，仅在reference做了一些手动添加/修改。

Codex 是什么

Codex 是 OpenAI 的编程代理，能够读取项目、修改文件、运行命令、执行测试、审查代码，并通过 Skills、Plugins 和 MCP 连接更多工具。它常用的两个入口是：

  • Codex CLI：在终端内工作，适合熟悉命令行、需要脚本化或 CI 自动化的用户。
  • Codex Desktop App：在 Windows 或 macOS 中以图形界面管理项目、多个任务、差异审查、终端、自动化和 Plugins。

* Codex 会真实读写文件和执行命令。开始前建议使用 Git 提交当前状态，并为它选择最小必要的文件和网络权限。

常用 CLI 命令

命令 用途 示例
codex 启动交互式终端界面 codex
codex exec / codex e 非交互执行，适合脚本和 CI codex exec "运行测试并总结失败原因"
codex resume 继续之前保存的会话 codex resume --last
codex fork 从旧会话分叉新方案 codex fork
codex review 审查未提交变更、某个提交或基准分支 codex review --uncommitted
codex app 从 CLI 打开 Desktop App codex app
codex doctor 诊断安装、认证、配置、Git 和运行环境 codex doctor
codex update 在当前安装方式支持时更新 CLI codex update
codex mcp 添加、删除、登录和查看 MCP Server codex mcp list
codex plugin 安装、查看和删除 Plugin codex plugin list
codex completion 生成 Bash、Zsh、Fish 或 PowerShell 补全脚本 codex completion powershell

常用启动参数

参数 用途 示例
-C, --cd <path> 指定工作目录 codex -C D:\Blog\hugoStackBlog
-m, --model <model> 本次运行使用指定模型 codex -m <model>
-i, --image <path> 把截图、设计图或架构图加入首轮上下文 codex -i error.png "修复截图中的错误"
--search 启用实时网络搜索 codex --search
-s, --sandbox <mode> 选择 read-only、workspace-write 或 danger-full-access codex -s workspace-write
-a, --ask-for-approval <policy> 控制何时需要人工批准 codex -a on-request
--add-dir <path> 额外授权一个可写目录 codex --add-dir D:\Shared
-c, --config key=value 仅为当次运行覆盖 config.toml codex -c key=value

* 不要在日常开发机器上随意使用 --yolo 或 danger-full-access，它们会绕过常规批准或沙箱保护。

/ 斜杠命令

在 Codex CLI 输入框中键入 / 会打开命令列表。命令会随版本和当前环境变化，以实际弹出列表为准。

会话与上下文

命令 用途
/new / /clear 在当前 CLI 中开始新会话
/resume 继续已保存的会话
/fork 从当前会话分叉新会话
/rename 为当前会话命名
/compact 压缩长对话，用摘要保留重点并释放上下文
/side / /btw 开一个临时侧边对话，不打断主线
/mention 把指定文件或文件夹附加到对话
/copy 复制最近一次完成的回复

模型、计划与执行

命令 用途
/model 选择模型和推理强度
/fast 在当前模型支持时切换 Fast 模式
/plan 先制定方案，再进入实施
/goal 设定、查看、修改、暂停或继续长期目标
/personality 切换沟通风格
/agent / /subagents 查看或切换子代理线程
/ps 查看后台终端与最近输出
/stop 停止当前会话启动的后台终端

修改、审查与权限

命令 用途
/diff 查看 Git diff，包括未跟踪文件
/review 审查当前工作树
/permissions 在会话中收紧或放宽权限
/approve 对最近被自动审查拒绝的动作批准一次重试
/status 查看模型、权限、可写目录、Token 与上下文状态
/usage 查看账户用量和限额状态
/init 为当前项目生成 AGENTS.md 指令骨架

扩展与其他工具

命令 用途
/skills 浏览并选择可复用的 Skill
/plugins 浏览、安装、启用或禁用 Plugin
/apps 浏览 Apps / Connectors，并将它们加入提示词
/mcp 列出当前可用的 MCP 工具
/hooks 查看、信任或禁用生命周期 Hooks
/app 把当前 CLI 会话继续到 Desktop App
/feedback 向 Codex 维护团队发送问题与日志
/quit / /exit 退出 CLI

Codex 能调用的 Functions / Tools

Codex 不只是生成代码，它会根据任务调用工具。实际可用项取决于当前平台、权限、Skills、Plugins 和 MCP 配置。

  • 文件工具：搜索、读取、新建和修改项目文件。
  • Shell / Terminal：运行构建、测试、格式化、Git 和项目自带脚本。
  • Web Search / Browser：在权限允许时搜索新资料、阅读页面或测试网页交互。
  • MCP / Connectors：访问 GitHub、Slack、Google Drive、数据库等外部系统。
  • Skills：加载一套可复用的流程、检查标准、参考文件或辅助脚本。
  • Image / Artifact Tools：在支持的表面读图、生成图片，或创建文档、表格、幻灯片等产物。
  • Agents：将可独立的子任务交给多个代理并行处理，再由主线整合。

工具调用前后都应检查输入、权限和结果；涉及删除、发布、推送、付费或对外发送消息时，应明确要求 Codex 先征求确认。

Codex Desktop App

安装与创建项目

a. 下载 Windows 或 macOS 版 ChatGPT Desktop App，打开后登录 ChatGPT 账户。
b. 在左上角切换到 Codex，选择 Open folder / Add project。
c. 只授权与任务有关的项目目录，例如 D:\Blog\hugoStackBlog。
d. 创建新对话（Thread / Chat），说明目标、限制、需要验证的内容和不可修改的范围。

常用快捷键：

操作 Windows / macOS
命令菜单 Ctrl/Cmd + Shift + P 或 Ctrl/Cmd + K
打开文件夹 Ctrl/Cmd + O
新对话 Ctrl/Cmd + N
搜索对话 Ctrl/Cmd + G
开关侧边栏 Ctrl/Cmd + B
开关终端 `Ctrl + ``
打开审查页 Ctrl + Shift + G

用 @filename 精确引用文件

@filename 会搜索并引用当前任务所属项目中的文件。在输入框键入 @ 和部分文件名，再从「文件」候选中选中目标，Desktop App 会将它作为明确上下文加入请求。与「帮我看一下代码」相比，指向具体文件更快、更准确，也能减少不必要的上下文。

先确认项目目录

@ 不会搜索整台电脑，它只能从当前项目已附加的文件夹中查找文件。即使在提示词中手动写了其他磁盘的路径，当前任务的主工作目录也不会因此自动切换。

以本博客项目为例：

a. 在 Desktop App 按 Ctrl+O。
b. 选择 D:\Blog\hugoStackBlog。
c. 为该目录新建一个 Codex 任务。
d. 确认新任务的工作目录为 D:\Blog\hugoStackBlog。
e. 输入 @codex，在「文件」分类中选择 codexUserGuide.md。

如果使用 Project，也可以打开 Edit project → Add folder，加入正确目录并将它设为 Primary。新任务会以 Primary folder 作为默认工作目录；其他已附加文件夹仍可用于文件搜索和读写。

/ 命令与 Skill

Desktop App 输入框中键入 / 可查看当前版本支持的操作。常用项包括：

  • /plan：先产生可审阅的计划，适合范围尚未完全明确的任务。
  • /goal：为长时间或多阶段任务设定持续目标。
  • /review：审查当前修改，优先查找缺陷、回归和测试缺口。
  • /status：查看当前模型、权限和会话状态。
  • /mcp：查看已连接的 MCP Server 和工具。
  • /feedback：发送产品反馈。

Skill 是针对某类任务的可复用工作流，例如「创建并验证 PDF」、「编辑并渲染 Word」或「生成博客文章」。

  • 在 Skills 页面浏览已安装的 Skill。
  • 在命令菜单中选择 Skill，或按当前界面提示调用。
  • 在需要精确指定时，使用 $skill-name 显式调用。
  • CLI 中对应命令是 /skills（复数），不要把 Skill 和 Plugin 混为一个概念。
1

$documents 请把 @notes.md 整理成一份 Word 文档，生成后渲染检查每一页。

Automations / Scheduled Tasks

Automations 现在在界面中也可能显示为 Scheduled，用于按时间表、周期或当前对话的轮询节奏自动运行任务。

适合场景：

  • 每天检查构建或测试状态。
  • 持续轮询 PR、CI、部署或其他长时间操作。
  • 每周整理代码库变更、依赖或异常报告。
  • 配合 Skill 与 GitHub、Slack 等 Plugin 执行标准化流程。

创建时应写清：每次运行要做什么、在什么时间运行、什么情况需要报告、什么情况应停止，以及是否回到当前对话。

1
2
3

每个工作日 09:00 检查这个项目的测试和依赖状态。
只读取项目并运行已有检查，不要自动修改、提交或推送。
如果全部正常则简短记录；如果失败，请报告失败命令、关键错误和建议的下一步。

本地项目的定时任务需要电脑开机、Desktop App 运行且项目目录可用。Git 项目可选择直接在当前工作目录运行，或在独立 Worktree 中运行；会改代码的后台任务优先使用 Worktree，避免与手头未完成的修改冲突。

Plugins

Plugin 是可安装的能力包，可以包含：

  • Skills：可复用的指令、参考资料、模板与脚本。
  • Connectors / Apps：连接 GitHub、Gmail、Google Drive、Slack、Notion 等服务。
  • MCP Tools：以结构化参数读取外部数据或执行操作。
  • Hooks、浏览器能力和 Scheduled Task Templates：在 Plugin 需要时提供更完整的工作流。

使用方式：

a. 在 Desktop App 左侧打开 Plugins。
b. 搜索并安装所需 Plugin，阅读它请求的权限。
c. 如果需要连接外部账户，完成登录与授权。
d. 安装后新建对话，直接描述目标，或键入 @ 明确选择 Plugin / Skill。

1

@GitHub 查看这个仓库最近失败的 CI，先总结失败原因和受影响的提交，不要修改代码或发送消息。

Plugin 可用性受账户方案、工作区管理策略、当前平台与 Plugin 自身限制影响。卸载 Plugin 不一定会自动断开它使用的 Connector，如需完全取消授权，还应到连接管理中检查。

多对话、多代理与 Worktree

Desktop App 适合同时跟踪多个任务。较大任务可以分为「查找安全风险」、「补测试」和「检查可维护性」等可独立子任务并行处理，最后由主对话整合。

Git Worktree 可以给每个对话一份独立工作区，避免多个代理同时修改同一份文件。但它不会自动消除架构冲突：并行前仍然应划分清晰的文件边界和验收标准。

Review、预览与终端

  • 使用 Review 查看变更文件和 diff，在提交前逐项检查。
  • 使用集成终端运行测试、构建、格式化和 git status。
  • 支持的文档、表格、演示文稿、PDF 和 HTML 可在 App 中预览。
  • 在可预览的文件或界面上添加 Annotation，可以把反馈精确指向某一行、某个组件或某个区域。
  • 要求 Codex 报告每个产物的保存路径、它运行的检查和尚未覆盖的风险。

如何写出更好的 Codex 任务

一个实用提示词通常包含以下部分：

1
2
3
4
5
6

目标：最终要产生什么结果。
上下文：应该阅读哪些文件、文档或外部资料。
范围：可以修改什么，不可以修改什么。
验证：需要运行哪些测试、构建、渲染或人工检查。
交付：最后应该列出文件、结果、风险和下一步。
安全：是否允许删除、提交、推送、发布、访网或对外发送消息。

对大任务，先用 /plan。对长时间结果，用 /goal。对精确文件，用 @filename。对标准化流程，用 Skill。对外部服务和工具，用 Plugin / Connector / MCP。对周期性任务，用 Automation。

安全与常见问题

为什么 Codex 一直询问批准？

因为当前操作超出了沙箱、可写目录或网络规则。先确认命令、目标路径和影响，再针对性批准，不要为了方便一次性开放全部权限。

为什么 Codex 找不到文件？

检查当前项目根目录，使用 @filename、CLI /mention 或 -C <path> 指向正确位置。项目外的目录可能还需要额外读写权限。

为什么安装 Skill 或 Plugin 后没有生效？

新安装的能力通常需要新建对话或 CLI Session。Plugin 若包含 Connector 或 MCP Server，还要检查是否已登录、授权、完成额外配置，以及工作区管理员是否允许使用。

为什么不建议让 Automation 直接推送代码？

定时任务在无人值守时运行，较宽权限会放大误修改、泄露数据和供应链风险。优先让它在独立 Worktree 中产生可审查的变更或报告，再由人员确认合并和发布。
